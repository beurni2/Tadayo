B. Moments B1's screens have no words or frame for

7. G01-create-failed: Ben named the club "Sunday people" and tapped Create; the club wasn't made. The name stays typed. Words for no connection and for a refusal (handoff 7's pattern: "Couldn’t … Check your connection and try again." and "Couldn’t … Try again."). Screen G01 (spec 04), 2.1 state 47 (G01-create.png).
8. G02-checking: Ben opened an invitation link from Messages, signed in; the app is asking the server about it. Nothing of the club or its people shows yet (handoff 4: "We’ll check the link before showing the club or its people."). Screen G02.
9. G02-invitation-failed: Ben tapped Accept this roster on Debby's invitation to Sunday people and the request failed with no connection. The roster stays; nothing has changed. Words for no connection and for a refusal. Screen G02, 2.1 state 02 (G02-invitation.png).
10. G03-approve-failed: Maya tapped Approve Leila (Kitchen table) and it failed. Words for Approve and for Decline failing, each for no connection and for a refusal; both actions stay. Never name who declined (book p30). Screen G03, handoff 4's G03-approve.
11. G05-club-details-failed: Ben opened Club details for Sunday people and it couldn't load. Give the loading words too ("Loading …"), in the form of handoff 7's tab loading and failure (noClubTabStates), with Retry. Screen G05, 2.1 state 20 (G05-club-details.png).

C. Four points kept for this stage's brief (handoff 7's brief, section 4)

12. G01-invite-people-accept-again: Ben's invitation list for Sunday people, where Sam accepted an earlier version of the roster and must accept this one (a link state the API calls "used"). Sam's row: its status words, and whether Share again or Create new link is offered. Handoff 4's G01-invite-people-revoked is the closest frame.
13. G01-pending-approve: the first roster's waiting screen when Ben, the creator, must approve a roster revision the server made because the person who accepted is named differently from the name Ben typed (FQ84). Handoff 4's G01-pending says "The club starts when another person accepts the same roster.", which isn't true here: show that Ben's own approval is needed, and the way to it (Review members).
14. G05-members-invite: where Ben shares and manages a later addition's link once Sunday people has started (FQ51's default reaches the invitation list only during setup, and a paused club's Club details offers "Invite someone", handoff 6's G05-club-details-paused). Draw Club details' members with Invite someone for an active club, or say where it belongs.
15. G02-changed-name: G02-changed when what changed is the viewer's own name: Ben accepted under the name "Benjamin", so the server made a new roster with "Benjamin · You". Handoff 2's G02-changed says "The people in Sunday people have changed.", which reads as if someone else changed.
