# Design handoff 7: what the ios lane needs

From the ios thread, 2026-11-05, for whoever writes handoff 7's brief. Each item names the state, what exists today, and what is missing. Until a frame arrives, each state is built from the spec and the delivered contracts and marked "built from spec" in `design/reference/INVENTORY.md` (T46). Stage B0 items come first: slice 11 builds them now.

Fixtures as before: Ben (no photo on these screens), `ben@example.com`, the code `529614`, en-US, 12-hour clock, New York. Frames at 393 by 852 points, light, with dark and the largest accessibility text size where the brief asks.

## 1. Sign-in and the profile (B0, slice 11)

Handoff 1 drew `A02-email`, `A02-code`, `A02-age` and `A03-profile`; handoff 2 corrected `A02-code-error`; handoff 4's `copy-contracts.json` holds the failure lines. None of the states below has a frame:

1. **`A02-email-sending`:** Send a code tapped, waiting for the server. Handoff 1 says the button keeps its height and label, refuses a second tap and exposes the busy state; how it looks isn't drawn.
2. **`A02-email-failed` and `A02-email-refused`:** "Couldn’t send a code. Check your connection and try again." and "Couldn’t send a code. Try again." exist; where the line sits on A02-email doesn't.
3. **`A02-code-verifying`:** Verify code tapped, waiting.
4. **`A02-code-verify-failed`:** "Couldn’t verify the code. Check your connection and try again." exists; its place (handoff 1's PDF p20 reserves two 13/18 lines between the field and Verify code for code errors) needs confirming for a network failure.
5. **`A02-code-resend`:** the minute has passed and no code has failed: the resend row shows the "Send a new code" action alone.
6. **`A02-code-resending`:** "Sending a new code…" appears only in handoff 1's PDF text (p20), in no JSON file. Confirm it, or give the line.
7. **`A02-code-resend-failed` and `A02-code-resend-refused`:** "Couldn’t send a new code. Check your connection and try again." and "Couldn’t send a new code. Try again." exist; their place on A02-code doesn't.
8. **`A02-age-saving` and `A02-age-failed`:** recording "I’m 18 or older" can fail. No line was delivered for it. The app uses "Couldn’t save your profile. Try again." meanwhile, since the confirmation is saved to the profile, and wants the real words.
9. **`A03-profile-empty`:** no name yet, so Continue is disabled. What the 68-point avatar shows with no name to take an initial from (handoff 1's PDF p21 asks for "an account-safe non-photo fallback when no readable initial exists" but doesn't draw it).
10. **`A03-profile-saving`, `A03-profile-failed` and `A03-profile-failed-network`:** the two save-failure lines exist; their place doesn't.
11. **A refused name:** a name longer than 40 grapheme clusters (FQ70) is refused by the API. Handoff 1 says to reject only an empty or whitespace name on the screen; no line says why a long one can't be saved.
12. **Back and leave:** A02-age's back chevron, after the code is verified: the app treats it as "Leave sign-in" (it ends the session and returns to A02-email, since Welcome, A01, comes in B1). Whether A03 shows a back chevron once the age is recorded ("going back also cannot bypass eligibility"): the app shows none. Confirm or correct both.
13. **The sign-in code line, if the founder rewords it** (FQ68, on a card in the ios thread): confirm the new wording of "Sent to ben@example.com".
13a. **`A02-code-verify-unavailable`:** Supabase answered Verify code with "too many requests" or a server failure, so it said nothing about the code: the digits stay and Verify code stays enabled. Neither the wrong-code words nor "Check your connection" fit (an answer came). No line exists; the app needs one (added 2026-11-05, from PR #19's review).
13b. **Leave sign-in that couldn't finish:** the phone couldn't forget the session (its keychain refused twice), so the app doesn't show A02-email over a session still kept. It shows the launch failure line with Retry, which tries again. While Leave runs, the app shows the launch screen, up to 15 seconds for Supabase's answer on a stalled network (a minute more if the token must be refreshed first). Confirm both, or give the words (added 2026-11-05, from PR #19's review).
