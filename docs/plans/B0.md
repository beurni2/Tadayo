## 2. Slices in order

**Workflow files decide the order** (`docs/GITHUB.md`, "Workflow files"):
- A workflow PR is ready only when no other PR of mine is open, because after it merges every open branch has to merge `main`, which the session can't push when it brings a workflow change.
- So no branch waits across a workflow merge: each feature branch that comes after a workflow is made from `main` once that workflow has merged. The `ci.yml`, `ios.yml`, `ops.yml`, `deploy-dev.yml` and `ios-release.yml` PRs (2, 9, 10b, 10c, 12) each go up with nothing else open.
- `ci.yml` comes second, so every later PR has `ci`. Its first push is the one-time test of whether the session can push a workflow file.
