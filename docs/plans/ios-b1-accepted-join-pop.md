## 3. The change

`apps/ios/Tadayo/Tabs/TabsView.swift`, the accepted invitation's destination (`ClubRoute.accepted`):

- **`acceptedAnswered(_:)`**, given to `InvitationDestination` as `answered`, which it calls after Accept or Retry returns: when the model is the one this screen shows (`shownAccepted === model`) and its state is `opening` (a club joined), it takes `.accepted` off every tab's path. `accept()` and `check()` await the root's `joined`, which has read the list again and let the invitation go, so this runs in the same main-actor job as the root's change, before SwiftUI's next update. An answer that comes after its screen was left with Back finds no `.accepted` left to take off, or, when another accepted invitation's screen has taken its place, a different `shownAccepted` (`rootInvitationChanged` sets it before pushing), and takes nothing off. Until now `answered` did nothing here, and the pop waited for the root.
- **The row's own check** (the review's S1): a changed roster's row with a kept link opens through `RootModel.openAccepted`, which checks the link (`present`); when that check answers that the account has joined (an Accept with no answer that the server made, then Not now, then the row again), the root's `joined` lets the invitation go as an Accept's does. `openAccepted` now gives back the model it showed (`@discardableResult`, `InvitationModel?`, nil only when the tabs don't show an account), and `TabsView.open(_:on:)` passes it to `acceptedAnswered` once it returns, so this join takes the screen off in the same action too. The app's `openAccepted` closure (`TadayoApp`) and `TabsView`'s property carry the model.
- **`leaveAccepted()`**, given as `leave` (Not now, Done and Close invitation): takes `.accepted` off, then the root closes the invitation, where until now it called only `closeInvitation()` and left the pop to the root's change.
- **`removeAccepted()`**: the loop `rootInvitationChanged` had, shared. `rootInvitationChanged` keeps calling it whenever the root lets its invitation go, for any way not covered above (a session ending, for one).

Nothing else moves: `RootModel`'s `joined` closure still keeps the club as the selected one, reads the list and lets the invitation go; Home opens on Kitchen table as before. Removing `.accepted` from `paths` directly doesn't call the path binding's setter, so the setter's `closeInvitation()` for Back isn't run twice.

Tests first, in `TadayoCore` (`RootModelInvitationTests`): `aChangedRowWhoseKeptLinkHasJoinedGivesBackTheModelItOpened` (the kept link's check answers joined: the model given back is `opening`, the root shows none, Kitchen table is selected) and `eachAcceptedRowGivesBackTheModelTheRootShows` (waiting, declined, and a changed roster with no link held: the model given back is the root's). Both failed to compile against the old `openAccepted`, which gave back nothing.

Not taken: deferring `rootInvitationChanged`'s pop to the main queue's next turn, which would wait for a time, not a state, and still pop from outside the action; and changing the UI test, whose check (Home with Kitchen table within 10 seconds of Accept) is right and stays as it is (T58).
