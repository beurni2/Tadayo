## 2. Decisions taken here (each noted in its PR)

- **The generator runs as SwiftPM's build plugin** (TECH-DESIGN section 4: "generated from `packages/contracts/openapi.yaml` on every build"; ADR-005). `Sources/TadayoAPI/openapi.yaml` is a relative symlink, `../../../../contracts/openapi.yaml`, so there is no copy to drift; Prettier skips symlinks, and `ci`'s Docker mount resolves a relative link. If Xcode refuses the link, the fallback (a copy plus a check) is a plan change raised in the PR.
- **Pins:** swift-openapi-generator 1.14.3, swift-openapi-runtime 1.13.4, swift-openapi-urlsession 1.4.0, each `exact:` (as SnapshotTesting's `exactVersion`). Transitive packages float, because `Package.resolved` is ignored (`packages/swift/.gitignore`): recorded in `docs/LIMITATIONS.md`.
- **Generated code is `internal`; TadayoAPI's public surface is hand-written.** `public` generated code gives 25 kinds of "public import … not used" warning under Swift 6.3.3 (142 lines), and nothing in `packages/swift` warns today. The façade exposes only what B0 calls (`getMe`, `updateMe`, `listClubs`), maps the contract's types to `TadayoCore`'s (`LocalDate`, `ServerClock` from `server_now`), adds the bearer token in a middleware, and turns every failure into a small error enum. It grows with each slice.
- **Naming strategy: idiomatic** (`displayName`, `.profileIncomplete`), since only the façade sees the names.
- **Dependency direction:** `TadayoAPI` depends on `TadayoCore`, never the reverse. `TadayoCore` keeps the models and view models and declares the protocols they call (`AccountService`, `AuthService`, `SessionStore`); `TadayoAPI` and the app implement them. `TadayoShare` depends only on `TadayoCore` and must later read the session (TECH-DESIGN section 4), so the session store's protocol and its keychain implementation live in `TadayoCore` (the keychain one under `#if canImport(Security)`, an in-memory one for Linux tests).
- **Supabase Auth by hand, no SDK.** supabase-swift would see the address and the tokens, a third-party SDK that sees personal data (`CLAUDE.md`, "Keep it simple"). Four calls, written in `TadayoCore` on `URLSession`, from GoTrue's source:
  - `POST /auth/v1/otp` `{email, create_user: true}` (never `data`, never PKCE);
  - `POST /auth/v1/verify` `{type: "email", email, token}`: `access_token`, `refresh_token`, `expires_in`, `expires_at`; `user` is dropped (it holds the address);
  - `POST /auth/v1/token?grant_type=refresh_token` `{refresh_token}`;
  - `POST /auth/v1/logout?scope=local` (the default scope is global).
  Headers: `apikey: <publishable key>` only, never the key as a bearer; `X-Supabase-Api-Version: 2024-01-01`. Errors are read from `x-sb-error-code` or the body's `code`, never from `message`, which can hold the address. The app never decodes the JWT (it carries the email); the account id comes from `GET /v1/me`.
- **Every request goes through an ephemeral `URLSession`** (no disk cache, no cookies), for the API and for Supabase; a test pins it (T11, T24, Q26; TECH-DESIGN section 12).
- **The session:** one keychain item, `AfterFirstUnlockThisDeviceOnly`, not synchronized, keyed by environment, holding the tokens and their expiry only. Refreshed 30 seconds before expiry (timed on `ContinuousClock` from receipt) and once after a 401 `UNAUTHENTICATED`, one refresh at a time (an actor). `refresh_token_not_found`, `session_not_found`, `session_expired`, `refresh_token_already_used` and `user_banned` end the session; a network failure, a 5xx or a 429 keeps it. The access group is the app group, `group.app.tadayo` (ADR-019), so one entitlement covers the app and the extension; if an unsigned simulator build refuses it, the item stays in the app's own group until slice 12 signs builds, and the PR says so.
- **Idempotency:** a UUIDv7 key (TECH-DESIGN section 4) made in `TadayoCore` (Foundation has no v7) when the action starts, kept with its exact body and `expected_version` for every retry (T19; PR #17's request hash answers `IDEMPOTENCY_CONFLICT` to any difference). The age and the name are two actions with two keys, the age first (`handoff-1/IMPLEMENTATION.md`: "records eligibility before profile").
- **Routing** (a `TadayoCore` model with Linux tests): no session, A02-email; session, `GET /v1/me`; `age_confirmed` false, A02-age; no `display_name`, A03-profile; else the tabs, where `GET /v1/clubs` decides: pending, the loading shell; failed, the failure state; both lists empty, the no-club states; anything else has no B0 screen and shows the failure state rather than pretending to be empty (T49). A 403 `PROFILE_INCOMPLETE` from any call sends the person back through `GET /v1/me`. The api lane's slice 8 serves `GET /v1/clubs` from the database, so `dev` gives a new account the real, empty lists (agreed in the api thread, 2026-11-05).
- **"Leave sign-in" and A02-age's back** end the session locally (`/logout?scope=local`, delete the item) and return to A02-email, since Welcome (A01) is B1. A03 has no back once the age is recorded ("Going back also cannot bypass eligibility"). Built from spec, noted in the inventory. Whether such an account is kept is FQ69's (slice 8).
- **The resend wait** counts 60 seconds from the app's own successful send on `ContinuousClock` (which keeps counting while the phone sleeps), in memory: a UI wait only, which Supabase enforces anyway (T1 untouched; INVENTORY's known difference). If iOS ends the app mid-sign-in, the person starts again at A02-email; a send within the minute gets the refusal line. Noted for TestFlight.
- **Copy** lives in `apps/ios/Tadayo/Localizable.xcstrings`, which the copy lint reads (Swift literals are invisible to it), with keys that don't trip the lint themselves (`\bsent\b` reads keys too). Strings come from the handoffs' contracts, newest namespace first (after #16: handoff 6, 5, then 4's cumulative file), with curly apostrophes.
- **The no-club header** (`noClubRootHeader`: wordmark, "+ Add", the account avatar) is content at the top of each tab, not toolbar items, so it draws the same on iOS 18 and under iOS 26's glass bars. The tab bar is the system `TabView` with `.tabItem` (iOS 17), SF Symbols `house`, `person.2`, `photo.on.rectangle`.
- **The wordmark** goes into a new app asset catalog from `design/reference/brand/brand-wordmark.pdf` and `-dark.pdf`, vectors preserved; labelled "Tadayo", not a header (X-17).
- **The Lab** stays in `LAB` builds only: a fourth tab, "Lab", once signed in, and a "Lab" button on A02-email, both only under `#if LAB`, plus a Lab-only "Sign out" so Gate 0's sign-in can be repeated (no Account screen until B6). Snapshots compose each screen directly, so neither appears in them.
- **The hosted test app is inert under XCTest:** no keychain read, no network at launch, so snapshot runs are repeatable and touch nothing (T53).
- **A second test target, `TadayoTests`** (hosted unit tests: the keychain store's round trip and its attributes, the routing with fakes), so the iOS 17 and 18 runs before Gate 0 test something: `ios_steps.py` skips only targets ending in `SnapshotTests`.
- **Supabase settings:** `TADAYO_SUPABASE_URL` and `TADAYO_SUPABASE_PUBLISHABLE_KEY` in `project.yml`'s Debug and Dev configurations, into Info.plist beside `TadayoAPIBaseURL`; Release has none and fails closed. B0.md section 1.2 says these two are public and go into the dev build's settings; TECH-DESIGN section 10's "never commit a key" means secrets (T56), and the PR says so.
- **Privacy manifests** gain the email address and the name (collected, linked, app functionality, not tracking); no `UserDefaults` is used, so no reason is needed.

## 3. PR 2: `ios/b0-api-client`, tests first

`packages/swift/TadayoAPI/`: `Package.swift` (tools 6.2, iOS 17, macOS 14; depends on `TadayoCore` and the three OpenAPI packages), `Sources/TadayoAPI/` (the symlink, `openapi-generator-config.yaml`, the façade, the auth middleware, the error mapping), `Tests/TadayoAPITests/` (a canned `ClientTransport`; no Prism in `ci`).

`packages/swift/TadayoCore/` additions: `Account`, `AccountService`, `AuthService`, `SupabaseAuth` (the four calls), `Session` and `SessionStore` (in-memory and keychain), `SessionManager` (refresh), `IdempotencyKey` (UUIDv7), `RootModel` (routing), `SignInModel` (A02's states), `ProfileModel` (A02-age and A03's states).

Tests, written before the code, Swift Testing with fake clocks and transports:
- the façade: `getMe` decodes `Me` (`ben`, `new_account`); `updateMe` sends PATCH with `Idempotency-Key`, `expected_version` and only the fields given; `listClubs`' `no_club` gives empty lists and its `server_now` reaches a `ServerClock`; 401, 403 `PROFILE_INCOMPLETE`, 409 `VERSION_CONFLICT` (with `current_version`), 429 and a 503 map to the error enum; a missing or altered `Cache-Control` is a failure, not a crash; the bearer is added, and never to the two public operations; no error's description carries a body or a header (T52);
- `SupabaseAuth`: each call's method, path, query, headers (no `Authorization` on otp, verify and token) and exact body keys; parsing ignores unknown fields and drops `user`; each error code maps to its delivered line (`failureStates`, `auth.firstSend.refused`, `auth.resend.refused`, `codeVerificationFailure`), every 403 from verify to `codeVerificationFailure`, a lost answer to the network line; `message` is never read;
- the session: refresh 30 seconds ahead, one at a time, once after a 401, the ending codes, re-reading the store after `refresh_token_already_used`; logout's order (refresh if expired, `scope=local`, delete, purge), offline deleting only;
- `IdempotencyKey`: version 7, variant bits, time-ordered, unique; the key and body kept across retries;
- `SignInModel`: Send enabled on a plausible address only, one request in flight, A02-code only after the server accepts, the address kept on failure; Verify on six digits and a tap, digits kept on failure; the 60-second wait from a successful send (a refusal doesn't reset it, a successful resend clears the digits and restarts it); Change email address keeps the address;
- `ProfileModel` and `RootModel`: each route in section 2's list; age before name; an empty or whitespace name refused locally; a name trimmed before sending; a save failure keeping the name;
- the ephemeral session configuration;
- no log line holds an address or a token.

Verified by `swift test` for both packages on Linux, `ci`'s swift job, `swift-format lint --strict`, and a local run against Prism (`pnpm --filter @tadayo/contracts mock`) for the façade. The `ios` workflow runs (the paths include `packages/swift/**`) but builds the app as before.
